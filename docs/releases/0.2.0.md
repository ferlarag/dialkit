# Dialkit 0.2.0

This release expands the stable facade from basic Calls and Messages to voice controls, media,
Messaging Services, TwiML, and typed webhook handling. It adds a separately packaged Messaging v1
generated crate. The pinned coverage audit accounts for 197 REST operations across API-2010 and
Messaging v1, plus 37 TwiML relationships and 16 webhook families.

## Compatibility and migration

The facade changes are additive relative to 0.1.0. Existing Calls, Messages, pagination, TwiML,
webhook validation, and TLS defaults retain their public entry points. Generated response/debug
formatting now redacts bodies and typed entities as a security correction.

Existing `Start::stream(name)`, `Start::siprec(name)`, and `Pay::prompt(text)` builders keep their
previous XML bytes. For new code, use `Start::stream_to(name, wss_url)`,
`Start::siprec_with_connector(name, connector_name)`, and `Pay::prompt_for(step, text)` to supply
the required attributes. These legacy builders remain compatibility exceptions until the next
major-version review; see the [compatibility assessment](../../specs/002-voice-sms-coverage/compatibility-report.md).

Update Cargo dependencies from `dialkit = "0.1"` to `dialkit = "0.2"`. Applications using only the
existing facade do not need to adopt the new domain handles.

in this order: `dialkit-core`, `dialkit-api-generated`, `dialkit-messaging-generated`, `dialkit`.
